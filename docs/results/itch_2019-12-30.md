# The order book on a real Nasdaq ITCH day: 2019-12-30

Until now the book had only seen real data at level 2 (Coinbase). This rebuilds order-by-order books from a full Nasdaq TotalView-ITCH 5.0 day and compares them with a reconstruction written without any of this project's code.

Input: `12302019.NASDAQ_ITCH50.gz` from https://emi.nasdaq.com/ITCH/Nasdaq%20ITCH/, 3,524,013,057 bytes, SHA-256 `ef03df46a27e6bda4dead017f84c2e3979df7211f02c7868b51d53fceb99c689`, 268,744,780 messages. Not committed. Reproduce with

    scripts/verify_itch_day.sh 12302019.NASDAQ_ITCH50.gz AAPL,MSFT,AMZN,TSLA,QQQ

which ran in about two minutes on a 2-core VM.

## How

`itch_extract` keeps the chosen stocks from the streamed day. `hft_itch_check` drives `hft::book::OrderBook` with them: A and F add, E and C execute, D cancel, U cancel and add with the new id, and X (cancel some shares) a same-price replace with the remaining size, which keeps the order's place in the queue. It logs the best bid and ask with their sizes after every change. `scripts/itch_reference_top.py` does the same from the specification with Python's struct module and dictionaries, and `scripts/compare_top.py` compares the two logs.

## Result

| Stock | Book messages | Adds | Top of book changes | Identical to the reference | Resting orders at end of day |
|---|---|---|---|---|---|
| AAPL | 1,512,179 | 698,744 | 424,660 | yes | 0 |
| MSFT | 1,215,912 | 576,026 | 600,038 | yes | 0 |
| AMZN | 524,554 | 232,975 | 67,604 | yes | 0 |
| TSLA | 527,741 | 228,513 | 126,458 | yes | 0 |
| QQQ | 2,373,946 | 1,111,822 | 1,364,095 | yes | 0 |

The book's 65,536 level price window is centred on each stock's median add price. Real days contain far away orders, from 0.0001 dollars to nearly 200,000 dollars in the same stock, and sub-penny orders below one dollar; the book rejects those outside its window or off its one cent tick (AAPL 41, MSFT 21, AMZN 6,001, TSLA 624, QQQ 16) and later messages that name them. None of them was ever the best bid or ask in the reference, which keeps them, so the identical logs are not an artifact of dropping them. AMZN loses the most because a 655 dollar window is narrow around 1,850 dollars.

The same day, through a different engine and the same reference, is in the lobkit repository (rxj0102/limit-order-book-matching-engine, docs/results/itch_2019-12-30.md); the three reconstructions agree.

## What this does not show

One day and five liquid stocks. The comparison is with a second reconstruction, not with Nasdaq's own book, though the closing cross prices in the file match the published closes. It checks the book only: the strategy, risk, OMS and gateway are not exercised by this replay, and nothing here is timed.
